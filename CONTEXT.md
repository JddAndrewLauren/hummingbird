# Context — personal task system (hummingbird)

Glossary for the personal GTD-style task system. The wayfinder map is [issue #1](https://github.com/JddAndrewLauren/hummingbird/issues/1). This file is a glossary only — no implementation details.

## Terms

- **Item** — anything the system tracks, whether or not it is yet an action: a capture sitting in Triage, a question in Grilling, a minted action, a finished thing. The umbrella term, and what a **mirror** holds one record per. Every action is an item; an item becomes an action once it is past triage (see **Stage**). Needed because the mirror holds the whole team, not just the startable part of it.
- **Stage** — where an item sits in the funnel: Triage → Grilling → Ready → In Progress → Blocked → Done (ADR-0009's decided vocabulary). Triage and Grilling are *pre-action* by definition — a capture has not been triaged and fog is not yet definable — so "is this an action?" is a question about stage, not about type.
- **Triage process** — the pair of *pre-action* stages, Triage and Grilling, together: everything the funnel has not yet decided is startable. The glossary defined each stage on its own but never named the pair until #357, which is also when Triage and Now's own view of the queue (`screens/triage-process-order.ts`'s `triageProcessQueue`) started naming it — the header's exact `captured · grilling` counts, not one undifferentiated "unsorted" total. Demo mode, which has no Grilling fixture of its own, keeps saying "unsorted".
- **Grill** — an item-scoped interview gesture, run one typed turn at a time against an item carrying fog, that ends in a verdict (ADR-0023). The verdict is a *reading of whether fog remains*, never a stage in itself — the same cut **Severity** draws against **Tier**: a Grill only says what it found, and something else (the verdict → stage mapping) decides what that finding does to the item.
- **Grill draft** — an unfinished Grill's turns so far, owned by the core and device-local (never a Grill record, never synced) — the property that makes closing a tab mid-interview a window closing, not a handover of unfinished work (ADR-0023, #356). Retained until its completion is acknowledged; discarding it is the one explicit, confirmed gesture.
- **Action** — the unit of personal project work: a concrete outcome that is *startable without further planning* and *finishable within one `size` label* (`deep` is the ceiling). Bigger than `deep` → it's a sub-route, not an action; not startable without more decisions → it's **fog**, not an action yet. Minted as an Action record by `/to-actions`. (Deliberately not "slice" — that word belongs to the twinion code pipeline, where it means a vertical, demoable cut.)
- **Route** — the plan a project carries: Destination, Fog, Notes, and the ordered list of minted actions. Owned and refreshed by `/to-actions`. Holds only what issues can't.
- **Destination** — what "done" looks like for a project, in the human's own terms.
- **Fog** — a segment of a route that can't yet be defined as an action, recorded with the open question that blocks defining it. Fog stays in the Route; everything definable gets minted.
- **Mint** — create the Action record for a defined segment (proposed labels, human-confirmed, landing in Ready). Every definable segment is minted immediately, startable or not; sequencing is carried by native `blocked by` relations, so closing an action automatically frees its dependents.
- **Step** — a microtask: one ~2–5-minute concrete physical action on an Action's checklist. Below action granularity — never an Action itself. Written by `/microtask`.
- **Plan** — the unticked half of an item's checklist: the **Steps** still proposing work. What a re-cut of the checklist is allowed to change, and the only half a decomposition ever owns. An item whose checklist is all **record** has no plan to protect.
- **Record** — the ticked half of an item's checklist: work done with the human's own thumb, and therefore history rather than a proposal. Never re-cut, re-worded or re-ordered by anything — a checklist that is finer after a **Replace** than the steps already ticked is mixed-grain and correct, because work already done does not get retconned to a grain that did not exist when it was done. Still readable by whatever re-cuts the **plan**, so the new plan can report finished work instead of re-proposing it.
- **Replace** — the explicit human gesture that swaps an item's **plan** for a freshly-cut one, at a different grain or from a different judgment. Explicit because it is destructive and because an implicit one cannot be told apart from a retry: absent the gesture, a re-decomposition of an item that already carries a plan is refused, never appended to. A replace is not a **Mint** — it re-cuts one item's steps and never changes what the item is.
- **Size** — how much of one sitting an item costs: `quick`, `normal` or `deep`. A claim about the work's shape, never about its importance and never about when it must happen — a `quick` item can be the most urgent thing there is. `deep` is the ceiling an **Action** must fit inside, which is what makes size the test for "is this an action or a sub-route?" rather than merely a label on one. Set deliberately, never inferred from a title's length; an item naming no size is one nobody has judged yet, which is not the same as a small one.
- **Energy** — what an item costs *you* rather than the clock: `low`, `medium` or `high`. The axis that explains why a `quick` item can be undoable at the end of a day and a long one fine — so it answers a different question from **size** and the two are never collapsed into one scale. Like size it is a cost, not a priority, and its absence is an unmade judgement rather than a claim of cheapness.
- **Context** — *where or with what* an item can be done: the tool, place or company it requires (`@computer`, `@errands`, `@phone`). An open vocabulary, not a fixed enum — the schema holds free text, because the set of places a person works is theirs. An item naming **no** context is doable anywhere, so absence widens rather than narrows, which is the opposite of how the absent **Delegation axis** marker reads. Distinct from a **Context source** and a **Context snapshot**, which are about the world the system watches, not about a condition on doing one thing.
- **Delegation axis** — whether a given item is one an agent could do, as opposed to one only the human can. The fourth axis, alongside **size**, **energy** and context, and the only one that answers *who does this* rather than *what this costs* — which is why it is not folded into context: context asks *where* can this be done and an item naming no context is doable anywhere, while an item naming no agent is the human's. There is no marker for "the human does it"; the absence *is* the marker, and the default. Set and cleared deliberately, never inferred from what an item looks like. It means there is agent work **left** here, not that an agent once touched this — so it is cleared when the agent finishes, or the next pass offers the same hand-off again.
- **External wait** — the only meaning of the Blocked state: the world is making the work wait (a callback, a part in the mail). Never used for inter-action dependencies — those are `blocked by` relations between minted actions.
- **Frontier** — what can be started right now: the live items that have reached Ready or In Progress and are not held back by an open `blocked by` relation. Computed at read time over the **mirror**, never a stored list and never a "picked" state — an item is on the frontier because of what it is, not because anyone put it there. An item a relation holds off it is not merely absent: the open blockers are nameable, so a short frontier can be explained rather than only being short.
- **Triage destination** — the one **stage** triage may promote a captured item into: Ready, once it is already startable. Never an arbitrary stage — triage does not send anything to Grilling, In Progress, Blocked or Done, and there is no Backlog to send it to; an item not ready to promote simply stays in Triage, which is not a destination at all. An item reaches Grilling exactly one other way — a `fog_remains` verdict from a completed Grill — never through triage. Whatever else the same triage sets — title, project, size, energy, context — moves with the promotion as one edit, not as several.
- **Capture source** — a source holding unprocessed thoughts, which the system *drains*: each item is created in Triage first, then acked in the source. An inbox the system empties. (Google Tasks is the first one.)
- **Capture unit** — what one labelling/entry gesture on a **capture source** is deemed to mean: the granularity at which the gesture mints exactly one capture, distinct from whatever identifies that capture once minted (ADR-0019). Google Tasks' unit and key are the same thing, the row; Gmail's are deliberately different — the unit is the **conversation** (Gmail's UI applies the label at thread granularity, so a labelled forward chain is one gesture) while the key stays the **message** (so a later message in a revived, already-completed conversation still mints a new capture rather than replaying a stale one).
- **Context source** — a source that is the authority for its own domain, consumed read-only at decision time and **never drained** — its records are never materialized as items. (Calendars are the archetype.)
- **State source** — a context source that reports the state of a thing and can therefore say *it's over*: a check that goes down and later up, a home sensor, a deadline the system itself watches. Its provenance names **the thing**, and successive occurrences are carried by one record's lifecycle rather than by new records.
- **Event source** — a context source that reports discrete happenings which never end: mail arriving, a meeting instance, a watched snapshot changing. Its provenance names **the occurrence**, because there is no *over* for the source to report — such a record leaves only by **Ack** or expiry. The distinction from a state source is declared when a source is wired, and it is not the same cut as whether the source is polled or pushed.
- **Mirror** — a device's derived, disposable, unified local read model of all the authorities (tasks from the task authority, events from context sources). Never a source of truth: deleting it loses nothing, and no record originates truth there. Named in ADR-0001; extended here to hold context-source replicas.
- **Ledger** — the complete retained roster: every item the **mirror** has ever known — live, Done, and archived alike — each shown with its current state, labelled rather than hidden. Derived at read time over the mirror's retained history, like the **Frontier**; deliberately *not* a chronicle — nothing records transitions, so the Ledger states what each item is now and when it was last touched, never what happened to it along the way. The one window where an archived item is still readable.
- **Urgency** — a derived, time-varying property of items, computed by consumers at read time over the mirror. Never a stored class and never a routing decision at ingestion: the same item may be background context on Monday and demand action ten minutes before its moment.
- **Deadline** — the moment the world imposes on an item: missing it has consequences. The only date urgency computation reads. Set deliberately, never inferred. Carries a day, and optionally a time of day when the consequence has an hour — a day-grained deadline is understood to run until that day ends.
- **Scheduled date** — a do-date the human chose for an item: the day they plan to work it. Sliding it costs nothing and it never feeds urgency. Distinct from the deadline — one is a consequence, the other a preference.
- **Alert** — a pushed context record: an event an external system raises at the app (a webhook, a tagged email), or that a **Rule** mints from a stream the system watches — carrying its source identity, a link back, and the **Severity** most recently reported for it. Its identity is one **Occurrence**, never a topic: this week's slide, not slides-in-general. It leaves the working view by resolution (the source says it's over), dismissal (the human waves it away — see **Ack**), or expiry (a source-declared lifetime) — and it never becomes an Action except by human gesture. One occurrence is one alert however many **Rules** match it at once, and it carries the highest severity among them — judgments made *together* resolve upward, never down.
- **Occurrence** — the single happening an alert is about, and the thing an **Event source** names as its identity. Identified by what is fixed about it rather than by what may still change — the pickup that was scheduled for Monday, not the Tuesday it slid to — so a source correcting itself updates one alert instead of raising a second. Never derived from anything the observer knows: re-reading the same happening tomorrow must name it the same way.
- **Live** — an alert still standing in the working view: not expired, and neither resolved nor waved away *since it was last raised*. Resolution and dismissal both silence the occurrence they were aimed at, never the thing forever — so a source re-raising afterwards is heard again, while re-sending the raise that was already settled stays quiet.
- **Severity** — how bad the thing an **Alert** reports currently is, as last assessed by whoever is authoritative for that alert. A reading, not a high-water mark: within one **Occurrence** it may fall as well as rise, and an authority that stops reporting a level leaves the alert with none. Distinct from **Tier**, which weighs a *delivery* rather than describing the record — and distinct from whether the alert *rings*, which is the **Delivery log**'s judgment and the only place severity is held to never falling.
- **Horizon** — how far back the wire carries *settled* alerts: a limit on what is transmitted, never on what is kept. A **Live** alert is never behind it, at any age; a settled one falls behind it once every stamp that settled it is old enough, and its record stays where it was written.
- **Event** — the one shape every **Rule** sees: something that happened, carrying provenance (which source, its identity there, when), a human-readable title, and whatever else its **Event kind** declares. Mail arriving, a meeting nearing, a watched snapshot materially changing, a deadline approaching, an alert pushed in from outside — all the same shape by the time a rule reads them. Every event is rule-eligible on its common core the moment its source exists; declared fields are a refinement, never a prerequisite.
- **Event kind** — the field-set family an **Event** belongs to, distinct from its source: two mail providers are one kind and two sources. An open registry, not a fixed vocabulary — a genuinely new shape is registered, never migrated to. A kind also declares whether its events *become* alerts when a rule matches, or already *are* alerts and only earn a delivery.
- **Rule** — a standing, human-authored declaration that events matching it must cut through the noise. The rule's existence *is* the importance judgment — human-set intent persisted as a record, kin to priority, never machine inference. A rule shapes records at birth (the alert it mints carries the severity it assigns) and emits deliveries; it never mutates an existing record. Default-deny: what no rule matches stays silent.
- **Promotion** — a rule matching an event at fire time and elevating it to a delivery. Computed fresh on every event and every timer tick; never stored as a class on any record.
- **Tier** — the delivery weight a rule assigns to what it emits (urgent or normal): metadata on the notification, never on the underlying record.
- **Delivery log** — the durable memory of what rang and why. Its job is silence: a delivery repeats only on a lifecycle transition (a new live occurrence, or an escalation above the highest **Severity** already rung for this one), never because a source re-said the same thing — and never because it lowered its assessment, which is good news and rings nothing.
- **Ack** — the explicit human gesture that marks an alert addressed, setting its dismissal — from the notification's action button (phone or wrist) or in the app. Swiping a notification away is not an ack: it ends that delivery and nothing else; the alert stays live and top-of-stack until acked or resolved.
- **Context snapshot** — the current state of a server-polled context source (a usage gauge, repo stats, site analytics), replaced wholesale on every poll. Renders as a tile with its "as of…" time; staleness is its own alarm.
- **Standing question** — a permanently-posed, domain-scoped question the app always answers at read time over the mirror ("when is the next race," "what's this weekend," "how long to the next vacation"). Its answer is computed fresh, never stored — the next-up question generalized to a domain. A standing question only answers: its **salience** may change *where its answer sits* among the others, never *whether it interrupts* — grabbing attention is the alert lane's job, wired separately. A question nobody has yet bound to a source is still posed, and still says so.
- **Salience** — a derived, time-varying property of a **standing question**: how much attention its answer deserves right now, and therefore where that answer sits among the others. Computed by consumers at read time, never stored. The sibling of **Urgency** and deliberately a different word — urgency belongs to an item and can demand action, while salience only ever decides placement. Its floor is *dormant*: the question is posed and answerable, but has nothing worth attention now. Dormant means **nothing to say**, never merely *far away* — a distant answer is still an answer, and still worth reading.
- **Cycle** — one pass of the sync engine: drain the **outbound queue**, then pull (delta-since-version normally, with the full sweep as the correctness backstop — ADR-0007 as amended), in that order. The order is the point — a device's own writes land before it re-reads, so a still-queued edit is never mistaken for a conflict against truth that predates it.
- **Outbound queue** — the durable, strictly ordered list of local changes not yet accepted by the authority. Written down before anything is sent, so a change survives a crash, a closed lid, or a week offline. Its order is preserved rather than optimized: creating a thing before editing it is a promise the queue keeps by never letting anything jump ahead.
- **Dead-letter journal** — where a change goes when it will never be sent: it lost to a newer authority value, or was rejected in a way no retry fixes. The change's *effect* is abandoned; the words the human wrote are not. Surfaced quietly ("1 edit didn't apply") for manual re-apply, **naming what the change was about** — an entry carries the entity and row it targeted, not only the queue attempt's own id, because a journal kept for manual re-apply that cannot say whose edit it holds is not one. The same instinct as parse being additive — reconciliation may discard an effect, never content a person produced.
- **View** — a window onto a sync engine, not a copy of one: it renders that engine's published state and asks it for things (a capture, an edit, a refresh), while owning no **mirror**, no **outbound queue**, no cursor, no **device credential** state and no **cycle** of its own. On the web host every browser tab and the installed app window is a view of the single engine the origin has (ADR-0010), so closing one is a window closing — never a handover of unfinished work. What a view *may* own is what the engine has no use for — where the credential rests, when it was entered — and it re-reads that rather than remembering it.
- **Device credential** — the single credential one device authenticates its whole sync with, and a thing the device is in exactly one of four states about: it *holds* one, it *has none*, it has one the authority has *rejected*, or nobody has yet *looked*. The fourth is not a credential state but a knowledge state, and it exists because a configured device must never read as unconfigured while it is still finding out — the same distinction drawn between a stale answer and no answer at all. "Has none" covers being unable to read as well as having nothing to read: a device that cannot reach its own store has no credential available to it, whatever the reason. The reason is worth telling a human, because it changes what they should do about it; it is not worth telling the sync engine, which would act identically either way.
