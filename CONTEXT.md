# Context — personal task system (hummingbird)

Glossary for the personal GTD-style task system. The wayfinder map is [issue #1](https://github.com/JddAndrewLauren/hummingbird/issues/1). This file is a glossary only — no implementation details.

## Terms

- **Item** — anything the system tracks, whether or not it is yet an action: a capture sitting in Triage, a question in Grilling, a minted action, a finished thing. The umbrella term, and what a **mirror** holds one record per. Every action is an item; an item becomes an action once it is past triage (see **Stage**). Needed because the mirror holds the whole team, not just the startable part of it.
- **Stage** — where an item sits in the funnel: Triage → Grilling → Ready → In Progress → Blocked → Done (ADR-0009's decided vocabulary). Triage and Grilling are *pre-action* by definition — a capture has not been triaged and fog is not yet definable — so "is this an action?" is a question about stage, not about type.
- **Action** — the unit of personal project work: a concrete outcome that is *startable without further planning* and *finishable within one `size` label* (`deep` is the ceiling). Bigger than `deep` → it's a sub-route, not an action; not startable without more decisions → it's **fog**, not an action yet. Minted as an Action record by `/to-actions`. (Deliberately not "slice" — that word belongs to the twinion code pipeline, where it means a vertical, demoable cut.)
- **Route** — the plan a project carries: Destination, Fog, Notes, and the ordered list of minted actions. Owned and refreshed by `/to-actions`. Holds only what issues can't.
- **Destination** — what "done" looks like for a project, in the human's own terms.
- **Fog** — a segment of a route that can't yet be defined as an action, recorded with the open question that blocks defining it. Fog stays in the Route; everything definable gets minted.
- **Mint** — create the Action record for a defined segment (proposed labels, human-confirmed, landing in Ready). Every definable segment is minted immediately, startable or not; sequencing is carried by native `blocked by` relations, so closing an action automatically frees its dependents.
- **Step** — a microtask: one ~2–5-minute concrete physical action on an Action's checklist. Below action granularity — never an Action itself. Written by `/microtask`.
- **External wait** — the only meaning of the Blocked state: the world is making the work wait (a callback, a part in the mail). Never used for inter-action dependencies — those are `blocked by` relations between minted actions.
- **Capture source** — a source holding unprocessed thoughts, which the system *drains*: each item is created in Triage first, then acked in the source. An inbox the system empties. (Google Tasks is the first one.)
- **Context source** — a source that is the authority for its own domain, consumed read-only at decision time and **never drained** — its records are never materialized as items. (Calendars are the archetype.)
- **Mirror** — a device's derived, disposable, unified local read model of all the authorities (tasks from the task authority, events from context sources). Never a source of truth: deleting it loses nothing, and no record originates truth there. Named in ADR-0001; extended here to hold context-source replicas.
- **Urgency** — a derived, time-varying property of items, computed by consumers at read time over the mirror. Never a stored class and never a routing decision at ingestion: the same item may be background context on Monday and demand action ten minutes before its moment.
- **Due date** — a deadline the world imposes on an item: missing it has consequences. The only date urgency computation reads. Set deliberately, never inferred.
- **Scheduled date** — a do-date the human chose for an item: the day they plan to work it. Sliding it costs nothing and it never feeds urgency. Distinct from the due date — one is a consequence, the other a preference.
- **Alert** — a pushed context record: an event an external system raises at the app (a webhook, a tagged email), or that a **Rule** mints from a stream the system watches — carrying its source identity, a link back, and the severity it was born with. It leaves the working view by resolution (the source says it's over), dismissal (the human waves it away — see **Ack**), or expiry (a source-declared lifetime) — and it never becomes an Action except by human gesture.
- **Rule** — a standing, human-authored declaration that events matching it must cut through the noise. The rule's existence *is* the importance judgment — human-set intent persisted as a record, kin to priority, never machine inference. A rule shapes records at birth (the alert it mints carries the severity it assigns) and emits deliveries; it never mutates an existing record. Default-deny: what no rule matches stays silent.
- **Promotion** — a rule matching an event at fire time and elevating it to a delivery. Computed fresh on every event and every timer tick; never stored as a class on any record.
- **Tier** — the delivery weight a rule assigns to what it emits (urgent or normal): metadata on the notification, never on the underlying record.
- **Delivery log** — the durable memory of what rang and why. Its job is silence: a delivery repeats only on a lifecycle transition (a new live occurrence, an escalation), never because a source re-said the same thing.
- **Ack** — the explicit human gesture that marks an alert addressed, setting its dismissal — from the notification's action button (phone or wrist) or in the app. Swiping a notification away is not an ack: it ends that delivery and nothing else; the alert stays live and top-of-stack until acked or resolved.
- **Context snapshot** — the current state of a server-polled context source (a usage gauge, repo stats, site analytics), replaced wholesale on every poll. Renders as a tile with its "as of…" time; staleness is its own alarm.
- **Standing question** — a permanently-posed, domain-scoped question the app always answers at read time over the mirror ("when is the next race," "what's this weekend," "how long to the next vacation"). Its answer is computed fresh, never stored — the next-up question generalized to a domain. A standing question only answers; it never notifies — grabbing attention is the alert lane's job, wired separately.
- **Cycle** — one pass of the sync engine: drain the **outbound queue**, then pull (delta-since-version normally, with the full sweep as the correctness backstop — ADR-0007 as amended), in that order. The order is the point — a device's own writes land before it re-reads, so a still-queued edit is never mistaken for a conflict against truth that predates it.
- **Outbound queue** — the durable, strictly ordered list of local changes not yet accepted by the authority. Written down before anything is sent, so a change survives a crash, a closed lid, or a week offline. Its order is preserved rather than optimized: creating a thing before editing it is a promise the queue keeps by never letting anything jump ahead.
- **Dead-letter journal** — where a change goes when it will never be sent: it lost to a newer authority value, or was rejected in a way no retry fixes. The change's *effect* is abandoned; the words the human wrote are not. Surfaced quietly ("1 edit didn't apply") for manual re-apply. The same instinct as parse being additive — reconciliation may discard an effect, never content a person produced.
- **View** — a window onto a sync engine, not a copy of one: it renders that engine's published state and asks it for things (a capture, an edit, a refresh), while owning no **mirror**, no **outbound queue**, no cursor and no **cycle** of its own. On the web host every browser tab and the installed app window is a view of the single engine the origin has (ADR-0010), so closing one is a window closing — never a handover of unfinished work.
